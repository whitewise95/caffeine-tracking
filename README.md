# 카페인 · 나의 카페인 기록

Apps in Toss WebView용 React + TypeScript + Vite MVP입니다. 섭취한 카페인과 경과 시간으로 **현재 잔존 카페인의 추정치**를 계산합니다. 의료기기나 측정 서비스가 아닙니다.

사용자가 제공한 [AGENTS.md](./AGENTS.md)와 [개발 프롬프트](./CODEX_INITIAL_PROMPT.md)를 프로젝트 루트에 적용했습니다.

## 실행

Node.js **24 이상**을 사용합니다. 현재 개발 도구의 요구 버전입니다.

```bash
npm install
npm run dev
```

기본 주소는 `http://localhost:5173`입니다. `/`, `/history`, `/knowledge`, `/settings` 경로를 지원합니다. 로컬 미리보기는 요청한 OLED 다크 디자인이며 `/?theme=light`로 Toss용 라이트 테마를 확인할 수 있습니다.

하단 메뉴는 홈·기록·지식·설정입니다. 지식 탭의 FAQ는 반감기, 흡수, 여러 잔과 천천히 마시기, 개인차, 수면, 디카페인, 음료별 함량을 설명합니다. 질문을 누르면 답변과 논문·공식 자료 링크가 펼쳐집니다. 답변은 앱에 포함되어 별도 네트워크 요청 없이 읽을 수 있고, 원문 링크를 여는 데는 인터넷 연결이 필요합니다. 연구 결과와 앱의 계산 가정을 구분하며, 카페인량은 추정치임을 안내합니다.

```bash
npm run dev:toss    # 공식 AIT Devtools를 연결한 SDK 모의 환경
npm run lint
npm test           # 계산·저장소·Toss adapter 단위 테스트
npm run test:e2e    # 375px / 390px 실제 Chrome 사용자 흐름
npm run build      # TypeScript 검사 + dist/ 생성
npm run build:toss # 위 빌드 + caffeine-tracking.ait 생성
```

브라우저 테스트는 기본적으로 설치된 Chrome을 사용합니다. Chrome 대신 Playwright Chromium을 쓰려면 `npx playwright install chromium` 후 `PLAYWRIGHT_BROWSER=chromium npm run test:e2e`를 실행합니다. 브라우저 테스트는 임시 테스트 저장소만 사용하며 미리보기의 사용자 기록을 변경하지 않습니다.

## 구현한 기능

- 홈: 인체 중심의 SVG 액체 시각화와 표면 찰랑임, 현재 추정 잔존량, 오늘 섭취량, 마지막 섭취 시각, 다음 밤 10시 예상량. 하단에는 음료별 추정 잔존량이 1mg 이상이거나 흡수가 진행 중인 섭취 기록을 보여주며 이전 날짜도 포함합니다. 섭취 초기에는 흡수에 따라 수치가 증가할 수 있습니다.
- 한 개의 Bottom Sheet 안에서 화면 전환: 카테고리별 음료 chip 목록 → 카페인 기록 화면, 각 카테고리의 + → 새 음료 입력 화면 → 카페인 기록 화면. 새 음료의 카테고리·아이콘·이름·카페인량은 한 화면에서 입력합니다. 기존 카테고리는 선택 버튼으로 고르거나 이름을 입력하고, 새 이름은 음료와 함께 저장합니다. 공백·탭·줄바꿈을 제외한 텍스트가 같으면 기존 카테고리를 재사용하며 빈 카테고리는 저장할 수 없습니다. 상단·브라우저·토스 뒤로가기로 목록에 돌아오면 음료 선택이 해제됩니다. 별도의 선택 해제 버튼은 없습니다. 음료 등록과 기록 화면은 같은 카페인량 조절 디자인을 사용합니다. 가운데 숫자와 양옆 ± 버튼, 하단 조절 바를 두며 한 번 누르면 1mg씩 바뀌고 길게 누르면 반복 간격이 점차 줄어듭니다. 기본 시각은 현재입니다. 선택적으로 `천천히 마셨어요`를 켜면 시작·종료 시각과 날짜를 입력하고 총 마신 기간을 확인합니다. 목록으로 돌아간 뒤 다시 선택하면 해당 음료의 기본 카페인량으로 시작하며 목록과 입력 화면을 동시에 보여주지 않습니다.
- 기록: 월간 캘린더와 선택한 날짜의 시간순 목록, 날짜별 총량·잔 수, 섭취량 및 시각 수정, 확인 후 삭제. 미래 날짜와 미래 달은 표시하지 않습니다.
- 설정: 기본 반감기 4시간 30분을 읽기 전용으로 표시하고 흡수·제거 계산식과 변수의 뜻을 설명합니다. 확인 후 전체 초기화와 앱 정보를 제공합니다. 수동 반감기 설정, 체감 설문, 응답 기반 보정은 제공하지 않습니다.
- 키보드 포커스 제한/복원, Esc·브라우저 뒤로가기, 줄바꿈, reduced motion, 저장 실패 표시, 손상된 저장 데이터 보호.
- 카테고리 관리: 설정과 음료 작성 화면의 `관리`에서 기본·사용자 카테고리를 추가·이름 변경·삭제합니다. 음료가 있으면 다른 카테고리로 모두 이동한 뒤 한 번에 저장하며 기록과 사진은 보존합니다. 손잡이를 길게 눌러 정렬하거나 `위로 이동·아래로 이동`을 사용합니다. 키보드는 스페이스로 시작, 방향키로 이동, 스페이스·Enter로 저장, Esc로 취소합니다. 음료 작성 중 관리 화면에 다녀와도 이름·사진·카페인량이 유지됩니다.

첫 실행은 **빈 기록**으로 시작합니다. 데모 섭취 이력을 실제 기록처럼 삽입하지 않습니다.

React state만 사용하며 별도 상태관리·라우터·차트 라이브러리는 추가하지 않았습니다. 아이콘은 Lucide, 인체/예측선은 직접 작성한 SVG입니다. TDS는 공식 FAQ상 선택 사항이므로 사용하지 않는 의존성을 추가하지 않았습니다.

## 계산과 데이터

`oral-uniform-intake-v2` 모델은 각 음료의 **흡수된 카페인 추정 잔존량**을 계산하고 합산합니다. 기본 기록은 한 시점에 섭취한 아래 식을 사용하고, 천천히 마신 기록은 같은 식에 섭취 시간 구간을 반영합니다.

```text
t = 섭취 후 경과 시간(h)
A(t) = doseMg × ka/(ka−ke) × (exp(−ke×t) − exp(−ka×t))
ka = 4.54 /h, ke = ln(2)/H /h, 생체이용률 F = 1 가정
H = 기본 4.5시간 = 4시간 30분 (고정)
현재 추정 잔존량 = Σ A(t)
```

`천천히 마셨어요`는 입력한 시작·마지막 시각 사이에 전체 용량을 일정하게 나눠 마신 것으로 가정합니다. 구간 내 각 섭취분의 흡수·제거를 적분하며, 마시기 전의 양을 미리 포함하지 않습니다. 제거 반감기를 늘리는 기능이 아닙니다. 시작은 마지막 시각보다 빨라야 하고, 미래에 마실 양은 기록할 수 없습니다. 날짜별 총량·잔 수는 마지막으로 마신 날짜를 기준으로 모읍니다.

[Terziivanov et al. (2003)](https://pubmed.ncbi.nlm.nih.gov/14674790/)의 집단 추정 흡수 속도 `4.54/h`를 참고합니다. 기본 제거 반감기 **4시간 30분**은 앱에서 정한 고정 계산 기준이며, 제거 속도는 `ke=ln(2)/4.5`(약 `0.154/h`)입니다. 이 기준은 연구의 `ke=0.139/h`(약 4.99시간)에서 직접 도출한 값이 아닙니다. 이 앱이나 개인의 잔존량 정확도가 검증됐다는 뜻은 아닙니다. 개인차·제형·음식·용량에 따른 변동을 실제로 식별하지 못합니다.

흡수 전 양은 별도로 계산하며 홈 mg에 더하지 않습니다. 한 시점에 마신 경우 그 순간의 흡수된 양은 0이고 기본 4시간 30분 모델에서는 처음 약 46.3분은 증가할 수 있습니다. 천천히 마신 경우 시작부터 흡수가 진행되므로 마지막 시각의 추정량이 0에서 시작하지 않습니다. 목록에는 흡수 전 양이 1mg 이상인 기록도 `흡수 중`으로 표시합니다(표시 기준일 뿐 생리학적 경계가 아님). 미래 섭취분은 현재량과 예측에서 제외하고 전날 기록은 자정 이후에도 이어서 계산합니다. 기기 시각이 되돌아가 기록 구간 안에 위치하면 밤 예측은 현재까지 마신 분량만 반영합니다. 반올림된 0mg도 실제 완전 제거를 뜻하지 않습니다. `LOW`, `LIGHT`, `FILLED`, `HIGH_VISUAL`은 **시각 효과용 구간**입니다.

변경 전 즉시 흡수식보다 초기 곡선과 계산값이 달라집니다. 저장된 원래 섭취량·시각을 변경하지 않고 새 식으로 화면 값을 다시 계산합니다.

선택 필드 `startedAt`이 없는 기존 기록은 단일 시각 계산을 유지합니다. 구간 기록의 `consumedAt`은 마지막 시각이며 수정에서 선택을 해제하면 시작 시각을 제거합니다.

답변 기반 반감기 조정은 추후 검토할 기능입니다. 현재 버전에서는 설문 화면, 응답 수집·관리, 체감 지속 시간 예측, 학습 및 반감기 보정 로직을 제거했습니다. 모든 화면은 기본 4시간 30분을 사용합니다.

기존 저장 데이터의 고정 반감기 5시간은 불러올 때 4시간 30분으로 적용합니다. 섭취량·시각 등 원래 기록은 유지하고, 새로 저장하는 데이터에는 4.5시간을 사용합니다.

기본 음료와 직접 만든 음료 모두 선택 후 하단의 `음료 삭제`를 사용할 수 있습니다. 같은 모달 안에서 삭제를 확인한 뒤 목록에서 제거하며, 기존 섭취 기록의 이름·양·시각과 사용자 카테고리는 보존합니다. 삭제한 음료의 사진 대신 기존 기록에는 저장된 기본 아이콘을 표시합니다. 기본 음료는 이 기기에서 제외한 음료 ID를 저장하므로 새로고침 후에도 나타나지 않으며, 직접 만든 음료는 저장된 음료 데이터를 제거합니다. 저장이 실패하면 목록을 유지하고 다시 시도할 수 있습니다. 모든 데이터 초기화 후에는 기본 음료 목록이 복원됩니다.

현재 모델: [문헌 근거표](./docs/research/caffeine-evidence.md), [흡수·제거 모델](./docs/research/oral-caffeine-model.md). 이전 개인화 설계 문서는 추후 검토용으로만 보관합니다.

기본 음료 8개의 카페인 수치는 모두 `sourceType: 'sample'`인 **참고용 예시값**입니다. 실제 값은 제품·브랜드·용량·추출 방식에 따라 다릅니다. 공식 브랜드 자료로 표시하지 않습니다. 커스텀 음료는 `sourceType: 'custom'`으로 구분합니다.

브라우저는 repository 내부 localStorage, Toss는 공식 SDK `Storage`를 사용합니다. 기존 저장 키를 유지하며 v1/v2/v3 데이터를 스키마 v4로 읽습니다. 사용자 카테고리와 해당 음료의 연결을 함께 보존합니다. 기본 카테고리는 커피·차·에너지음료·탄산이며, 기타 섹션과 기본 콤부차는 제외합니다. 기존 기타 카테고리에 직접 등록한 음료가 있으면 해당 카테고리를 함께 보존합니다. 새 기본 이름과 같은 기존 사용자 카테고리는 음료를 보존하며 합칩니다. 앨범 사진은 음료당 한 번만 최대 160×160px JPEG 썸네일(저장 문자열 48,000자 이하)로 저장하고 기록에서는 음료 ID로 참조합니다. 커스텀 음료의 카페인량은 1mg 단위 직접 입력과 조절 바가 연동됩니다. 섭취 기록과 커스텀 음료를 보존하고, 이전 반감기 설정과 체감 데이터는 계산에 사용하지 않는 호환성 보관 정보로만 남깁니다. 읽기만 할 때는 기존 저장 원문을 덮어쓰지 않습니다. 저장 성공 후에만 화면 상태가 바뀌며 손상된 음료 데이터는 자동 덮어쓰기하지 않습니다. 여러 기기 동기화나 외부 서버로 개인 기록 전송은 지원하지 않습니다. 설정에서 기기 변경, 토스 앱 삭제 및 기기 데이터 삭제 시 기록이 사라질 수 있으며 복구할 수 없음을 안내합니다. 초기화는 이 앱의 저장 키만 삭제합니다. [토스 공식 저장소 문서](https://developers-apps-in-toss.toss.im/documentation/common/file-storage/storage)를 Toss MCP로 확인했습니다.

## Apps in Toss 적용과 출시 전 확인

공식 MCP와 SDK 3.7.0으로 확인한 상세 근거는 [Toss 연동 조사 문서](./docs/toss-integration.md)에 있습니다.

- SDK 3.x `apps-in-toss.config.ts`, `webView`, `webBundleDir`, `ait build` 적용.
- `SafeArea.get/subscribe`, `graniteEvent`의 `backEvent`, `Screen.setIosSwipeBack`, `Storage` 연결.
- 추가 모달의 입력 화면에서는 뒤로가기로 음료 목록에 돌아오고, 목록에서는 모달이 닫힙니다. 시작·종료 시간을 누르면 같은 모달 안의 휠 선택 화면으로 전환합니다. 오전·오후 / 시 / 분은 상하 스와이프, 숫자 탭, 방향키로 선택하며 완료할 때만 반영합니다. 시간 선택 중 뒤로가기·취소·Escape는 원래 시간을 유지하고 기록 화면으로 돌아옵니다. 그 외 화면에서 닫기·Escape·저장 완료는 모달 전체를 닫습니다. 홈에서는 호스트의 기본 종료 동작을 사용합니다. 지연 저장이 끝나더라도 이미 돌아간 화면에서 추가 뒤로가기가 발생하지 않도록 방어합니다.
- 비게임 앱 공식 체크리스트는 **라이트 모드**와 floating 하단 탭을 요구합니다. 따라서 Toss 런타임은 라이트 테마를 사용하고, 일반 웹 미리보기는 요청한 OLED 디자인을 유지합니다.
- SDK 3.x는 과거 별도 Sandbox 앱 대신 **AIT Devtools와 실제 토스 앱 QR 테스트**를 사용합니다. Devtools는 모의 환경이며 실제 기기 확인을 대신하지 않습니다.

콘솔에서 등록한 appName을 사용해 빌드하세요. 현재 `caffeine-tracking`은 개발용 기본값이며 실제 콘솔 등록을 완료했다는 의미가 아닙니다.

```bash
TOSS_APP_NAME=실제등록한appName npm run build:toss
```

생성된 `.ait`를 콘솔에 업로드한 뒤, 콘솔이 제공하는 QR/`intoss-private://` 링크로 iOS·Android에서 여백, 네이티브 뒤로가기, swipe, 기록 저장, 경로 직접 진입을 확인해야 합니다. 정식 경로는 `intoss://{appName}/history`와 같은 형식입니다. 이 저장소 작업에서는 외부 배포·콘솔 등록을 수행하지 않았습니다.

## 서버/API

현재 MVP에는 로그인·서버가 필요하지 않습니다. 다음 단계에서 기기 간 동기화가 필요하면 계정별 기록/음료 API와 서버의 Toss 로그인 토큰 교환이 필요합니다. 브랜드별 공식 카페인 데이터를 제공하려면 출처·용량·갱신일을 관리하는 검증된 카탈로그가 필요합니다. 토큰과 서버 비밀정보는 클라이언트에 넣지 않습니다.
