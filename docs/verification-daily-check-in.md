# 일일 체감 팝업 검증

> 보관 문서: 아래는 2026-10-04 당시 구현·검증 기록입니다. 당시의 5시간 기준과 실행 결과는 그대로 보존합니다. 현재 앱은 4시간 30분을 고정 기준으로 사용하며 설문·응답 기반 보정은 제공하지 않습니다. 최신 동작은 [README](../README.md)와 [현재 모델](research/oral-caffeine-model.md)을 참고하세요.

> 이후 홈 체감 예측과 최근 7일 요약을 제거하고 설정에서 체감 응답을 관리하도록 전환했다. 현재 동작은 [체감 기록 검증](verification-feeling-journal.md)을 참고한다.

2026-10-04. 기존 홈의 시간 입력 카드를 세 가지 답변을 받는 중앙 모달로 변경했다.

## 동작

- 개인화가 켜져 있고 현지 날짜 기준 전날의 양수 카페인 섭취가 있으며 미답변이면 홈 진입 때 자동 표시한다. 13시간 대기는 제거했다.
- `오래 갔어요`, `비슷했어요`, `빨리 줄었어요` 중 하나를 선택한 뒤 저장한다. 질문 이유는 `나에게 맞는 체감 지속 시간 예측을 위해 물어봐요.`로 표시한다.
- 답변 저장은 해당 날짜의 재질문을 막는다. 닫기·Escape·뒤로가기는 응답을 만들지 않고 이번 방문에서만 숨긴다. 다시 실행하거나 화면으로 복귀하면 미응답을 다시 제안한다.
- 열린 팝업의 대상이 자정에 바뀌면 선택을 초기화한다. 이미 답한 팝업을 브라우저 앞으로가기로 복원해도 다시 표시하지 않는다.
- native dialog의 배경 비활성화, 키보드 이동, 포커스 복원, 스크롤 잠금, 작은 화면 스크롤, reduced motion을 적용했다. 기존 라이트/다크 토큰을 사용한다.
- 새 응답은 예측 스냅샷이 없어도 `daily-feeling` 종류로 저장한다. 실험적 **체감 지속 시간**만 +15분 / 유지 / −15분으로 보정하며 한계를 둔다. 잔존 mg 계산의 제거 반감기는 5시간이다.
- 기존 시간 구간·예측 비교 응답은 호환성을 유지하고 설정에서 수정할 수 있다. 새 방향 응답은 과거 정확도 평가의 관측으로 세지 않는다.

## 실행 결과

| 확인 | 결과 |
| --- | --- |
| `npm install --offline --no-audit --no-fund` | 설치 상태 확인 완료, 새 의존성 없음. 기존 설치 정책에 따라 fsevents/protobufjs 스크립트는 실행하지 않음 |
| `npm run lint` | 통과 |
| `npm run build` | TypeScript 및 Vite 통과 |
| `npm test` | 4개 파일, 96개 통과 |
| `npm run test:e2e` | Chrome 375×812 / 390×844, 전체 68개 통과 |

E2E는 날짜 경계, 전날 기록 없음, 세 답변, 저장 실패와 재시도, 중복 제출, 저장 중 뒤로가기, 다시 실행, 화면 복귀, 응답 수정·삭제, 기존 입력 호환, 기본 음료·커스텀 음료·기록·캘린더 흐름을 포함한다. 라이트/다크와 글자 200% 확대, 44px 이상 조작 영역, 가로 넘침, 키보드 이동을 확인했다. native dialog에서 Tab으로 브라우저 자체 UI에 초점이 넘어가는 경우를 허용하면서 배경 앱 컨트롤이 활성화되지 않는지를 검사한다.

독립 읽기 검토에서 자정의 오래된 대상, 저장 후 앞으로가기로 복원되는 응답 모달, 기존 정확도 보류가 새 자기보고 보정을 막는 혼합 이력을 발견해 수정했다. 마지막 혼합 이력 변경 후 96개 단위 테스트를 다시 통과했다. 토스 뒤로가기·iOS 스와이프는 [공식 이벤트 문서](https://developers-apps-in-toss.toss.im/documentation/common/screen/event)와 [스와이프 API](https://developers-apps-in-toss.toss.im/documentation/sdk/domains-api/screen/screen.setiosswipeback)를 확인한 기존 overlay 경로를 재사용한다. 이번 검증은 브라우저 환경이며 토스 실제 기기 시험은 포함하지 않는다.
