# Liquid Avatar

홈의 SVG 캐릭터는 추정 잔존 카페인량을 보여준다. 표정과 실루엣은 시각적 구분이며 피로, 집중력, 건강 상태나 의료적 위험도를 판단하지 않는다.

- 0–20mg: 처진 형태, 감긴 눈, 거의 정지. 정확히 0mg이면 액체와 기포를 표시하지 않는다.
- 20mg 초과–80mg 미만: 낮은 액체와 작은 호흡.
- 80–160mg 미만: 열린 눈, 부드러운 부유.
- 160–300mg 미만: 약간 넓고 탱탱한 실루엣과 곡선 눈.
- 300mg 이상: 크기는 더 커지지 않고, 코랄 테두리·눈과 간헐적인 0.45px 떨림을 사용한다. 주변 빛은 줄인다.

`LiquidAvatar`는 `caffeineMg`, 선택적인 `maxCaffeineMg`, 기록 성공 이벤트인 `intakePulse`, 흡수 중인 기록 수 `absorbingCount`를 받는다. `maxCaffeineMg`의 기본값 300mg은 그림을 채우는 기준일 뿐, 섭취 권장량이나 안전 한도가 아니다. 수치 표시는 이 값으로 제한하지 않는다. 기존 `CaffeineBodyVisual`은 호환 래퍼로 유지한다.

계산 모델은 변경하지 않는다. 새 기록은 빛 방울과 파동으로 1.4초간 응답하지만, 실제 액체 높이는 흡수 모델의 추정값만 따른다. 시간 경과에 따른 높이 변화는 부드럽게 보간한다. 새로고침이나 홈 재진입에는 기록 반응을 재생하지 않는다.

흡수 중에는 `AvatarDrinking`이 한 잔을 입에 댄 고정 자세를 표현한다. 오른팔은 몸 윤곽과 넓게 연결되고 앞쪽 유리 반사로 굽힌 팔을 표현한다. 입 가까이의 커피잔 손잡이를 감싸며, 팔의 기본 반사광은 무채색이고 핑크 테두리는 몸과 같은 액체 높이 마스크 안에서만 보인다. 액체가 팔에 닿지 않으면 팔은 유리색을 유지한다. 또한 컵·팔·몸은 같은 변형 그룹 안에 있어 서로 떨어지지 않는다. 잔을 쌓거나 마시는 동작을 반복하지 않는다. 상세 잔존량 목록과 같은 미흡수량 1mg 표시 기준을 사용하며, ‘흡수 중 N잔’의 수치는 30초마다 갱신되는 현재 시각·기록 추가/수정/삭제에 따라 달라진다. 미래 기록과 흡수가 끝난 기록은 제외한다. 마지막 기록의 흡수가 끝나면 기본 자세로 돌아간다.

흡수 중일 때만 액체 안의 `avatar-absorption-glow`가 6초 주기로 잠깐 밝아졌다가 사라진다. 몸과 액체 수면 마스크로 잘라 액체 밖으로 번지지 않게 한다. 평상시 액체의 중심광은 일정하게 유지한다. 효과가 추정 mg나 액체 높이를 바꾸지 않으며, 새로고침 후에도 흡수 중이면 자세와 효과를 유지한다. 모달·백그라운드에서는 효과를 정지하고, 동작 줄이기 설정에서는 자세만 유지하고 주기적인 빛을 끈다.

캐릭터를 탭하거나 키보드 Enter·Space로 누르면 액체 안의 별도 빛이 즉시 켜지고 0.85초 동안 부드럽게 사라진다. 연속 탭은 이 효과만 다시 시작하며, 기존 흡수 발광의 주기·액체 움직임·기록·추정량을 변경하지 않는다. 같은 몸과 수면 마스크를 사용하므로 비어 있는 팔이나 0mg 상태는 빛나지 않는다. 동작 줄이기 설정에서는 반복 애니메이션 없이 짧은 고정 강조로 반응한다.

`AbsorptionInfo`는 SVG 밖의 44px 이상 HTML 버튼으로 ‘흡수 중 N잔’과 느낌표 아이콘을 표시한다. 탭하면 설명 말풍선이 열리고, 닫기·Escape·바깥 탭으로 닫을 수 있다. 글자 확대 시 말풍선 내부를 스크롤할 수 있으며, 흡수 중인 기록이 없어지면 설명도 사라진다. 혈중 농도 정점(보통 섭취 30~120분 후)을 흡수 완료 시점으로 표현하지 않고, 앱의 미흡수량 1mg 표시 기준과 실제 측정의 차이를 설명한다. 근거는 [Terziivanov 외, 2003](https://pubmed.ncbi.nlm.nih.gov/14674790/)과 [Willson, 2018](https://pmc.ncbi.nlm.nih.gov/articles/PMC6247400/)이며, 링크는 기존 `ExternalLink`를 통해 연다.

SVG clipPath, gradient, 작은 영역에 고정된 Gaussian blur와 CSS transform/opacity를 사용하며 외부 이미지, WebGL, 애니메이션 라이브러리를 추가하지 않는다. 기포는 최대 9개다. 모달이 열리거나 문서가 백그라운드일 때 애니메이션을 멈추고, `prefers-reduced-motion`에서는 모든 움직임과 기록 효과를 끈다. 어두운 테마의 소재 토큰으로 표현한다.

발광 소재는 낮은 불투명도의 액체, 여러 겹의 수면선, 채워진 영역의 테두리 반사광으로 구성한다. 내부 S자 빛줄기는 표시하지 않는다. blur 자체를 애니메이션하지 않는다. 기포 최대 9개와 작은 입자 최대 18개가 서로 다른 주기로 흐른다. 형광색은 캐릭터 내부와 가장자리에 집중하고, 0mg에서는 액체 발광을 끈다.

홈의 추가 액션은 캐릭터 오른쪽 발치의 `AvatarAddButton` 유리컵이다. 컵 전체를 버튼으로 사용하고 접근성 이름은 ‘카페인 추가’로 유지한다. ‘한 모금 채워볼까요?’ 문구와 작은 곡선 화살표로 액션을 안내한다. 기존 추가 시트와 기록 반응을 그대로 사용한다. 컵은 작은 고정 SVG gradient/blur로 표현하며 별도 이미지나 라이브러리를 추가하지 않는다. 글자 확대·좁은 공간에서는 컵과 문구를 캐릭터 아래 별도 줄에 두어 겹침을 막는다.


## 휴대폰 기울기와 액체

`useDeviceTilt`는 표준 `deviceorientation` 이벤트의 beta/gamma와 화면 회전각을 화면 안의 중력 방향으로 바꾼다. 평평하게 놓인 기기는 화면 안의 중력 방향이 불명확하므로 마지막 유효 방향을 유지한다. 자석/나침반이나 카페인 계산에는 영향을 주지 않는다.

`useAvatarLiquidMotion`은 감쇠 스프링으로 방향을 따라간다. `liquidWaves`의 느린 큰 물결과 방향·속도가 다른 작은 잔물결을 겹쳐 평상시에도 수면이 흐른다. 기울기 토글을 꺼도 기본 물결은 유지한다. 회전 속도에 따라 파고가 커졌다가 천천히 잦아들며, 액체가 적거나 캐릭터가 거의 가득 찼을 때는 파고를 제한한다. SVG의 실제 몸 윤곽 안을 일정 간격으로 샘플링하고 각 점에서 물결 높이를 빼서, 물결이 이동하고 기울어져도 채워진 면적을 유지한다. 하나의 수면 경로를 액체·몸 테두리·마시는 팔의 핑크빛 마스크가 공유하며, 기포는 같은 회전 좌표계에서 중력 반대 방향으로 올라간다. 흡수 자세가 바뀌어도 현재 움직임은 이어진다. React 전체를 프레임마다 다시 렌더링하지 않고 SVG 속성을 최대 30fps로 갱신한다.

설정의 ‘애니메이션’ 토글에서 켜기·끄기를 선택하며, 홈에는 별도 센서 연결 버튼을 표시하지 않는다. 기본값은 꺼짐이다. 선택은 `settings.tiltAnimation`으로 기존 Repository에 저장하고 네이티브 권한과 독립적으로 유지한다. 꺼져 있으면 센서 이벤트를 구독하지 않는다. 토글을 직접 켤 때는 저장을 기다리기 전에 권한을 요청하며, 거부되면 꺼짐을 유지한다.

저장된 ON은 앱에서 설정을 불러온 직후와 포그라운드 복귀(visibilitychange·pageshow)에 기존 네이티브 허용 복구를 시도한다. 진행 중인 요청만 합치며 실패한 결과를 문서 전체 수명 동안 재사용하지 않는다. 복구에 새 사용자 동작이 필요하면 선택은 ON으로 유지한다. 이후 사용자가 하단의 다른 탭을 누를 때 해당 실제 클릭 핸들러에서 권한을 동기적으로 요청하고, 허용·취소 응답을 받은 뒤 선택한 탭으로 이동한다. 대기 중에는 다른 탭 입력을 막아 중복 요청·이동을 방지한다. 이미 연결됐거나 명시적으로 거부된 권한, OFF, 동작 줄이기에서는 탭 이동 시 다시 요청하지 않는다. 설정의 별도 ‘센서 권한 허용’ 버튼으로 명시적 거부를 재시도할 수 있다. 캐릭터를 직접 누를 때도 ON 상태이며 권한이 필요하면 즉시 요청한다. 명시적 거부 후의 캐릭터 탭은 사용자의 재시도로 처리하고, 이미 연결됐거나 요청이 진행 중이면 중복 요청하지 않는다. 액체가 0mg이어도 연결할 수 있으며 기존 발광 효과는 유지한다. OFF·동작 줄이기에서는 캐릭터 탭으로 권한을 요청하지 않는다. 기록 버튼 등 다른 일반 입력에서는 요청하지 않는다. 권한 상태 구독과 자동 복구는 분리되어 있어 화면 마운트 자체가 권한 창을 띄우지 않는다. iOS WebView가 새 문서에서 재허용을 요구하는 시스템 창을 앱 저장이나 자동 클릭으로 없앨 수는 없다.

센서가 없거나 전달되지 않는 환경에서는 기본 수면 효과를 유지한다. 모달·백그라운드에서는 움직임을 멈추고, `prefers-reduced-motion`에서는 기울기와 잔물결을 끈다. 기록이나 추정 mg는 움직임에 영향받지 않는다.

- [Toss WebView 권한 안내](https://developers-apps-in-toss.toss.im/documentation/common/permission): 일반 Web API를 사용하며 확인되지 않은 센서 SDK를 추가하지 않았다.
- [W3C Device Orientation and Motion](https://www.w3.org/TR/orientation-event/): 좌표 변환, 센서 권한, 화면과 센서 좌표의 차이.
- [MDN 센서 권한 요청](https://developer.mozilla.org/en-US/docs/Web/API/DeviceOrientationEvent/requestPermission_static): HTTPS/secure context와 직접 사용자 동작이 필요한 환경.

`liquidGravity.test.ts`는 액체 면적 보존·화면 회전·스프링 안정화를 검사한다. `liquid-gravity.spec.ts`는 375/390px에서 가상 센서 입력으로 좌우·뒤집기·화면 회전·권한 거부와 재시도·모달 정지·동작 줄이기·흡수 자세 전환을 확인한다. `tilt-animation-setting.spec.ts`는 토글의 켜기·끄기, 새로고침 후 유지, 새 문서의 기존 허용 복구, 탭 이동 전에 실제 사용자 활성화로 권한 요청·응답 대기, 허용·취소 후 이동과 중복 요청 방지, 캐릭터 탭의 권한 복구·발광 유지·중복 요청 방지, 포그라운드 복구, 명시적 권한 재요청, 미지원 환경과 저장 실패를 확인한다. 실제 Android/iOS Toss 앱의 센서 전달과 성능은 HTTPS 환경의 실기기에서 추가 확인해야 한다.
