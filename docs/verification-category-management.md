# 카테고리 관리 검증 — 2026-10-05

## 구현

- 설정의 `카테고리 관리`, 음료 작성 중 카테고리 옆 `관리`에서 진입한다. 하단 주요 메뉴는 홈·기록·지식·설정을 유지한다.
- 음료 작성 화면은 관리 화면에서 숨긴 채 유지한다. 돌아오면 이름·사진·카페인량이 남으며 선택한 카테고리의 이름 변경은 ID 기준으로 반영한다. 선택했던 카테고리가 삭제되면 다른 카테고리를 선택하도록 안내한다.
- 기본·사용자 카테고리의 추가, 이름 변경, 삭제를 지원한다. 기존 NFC·공백 비교 규칙으로 중복 이름을 막는다. 음료가 있는 카테고리는 목적지를 선택해야 삭제되며 목적지가 없으면 새로 만들 수 있다.
- 이름과 순서는 v4의 선택 필드 `categoryCatalog`, 기본 음료 이동은 `defaultDrinkCategoryOverrides`에 저장한다. 카테고리 삭제와 음료 이동은 같은 Repository 저장 한 번으로 처리한다. 기록·사진·삭제한 기본 음료 상태를 보존하고, 저장 성공 후에만 화면 상태를 바꾼다.
- 손잡이 350ms 누르기로 이동을 시작하며 놓을 때 저장한다. 가장자리 자동 스크롤, 터치 취소, 화면 이탈, Escape 취소를 지원한다. 관리 메뉴의 위·아래 이동과 키보드 정렬도 제공한다. 저장 실패 시 기존 순서를 유지하고 재시도할 수 있다.

375×812px, 390×844px에서 밝은/어두운 테마와 글자 200% 확대를 확인했다. 카테고리 관리 터치 영역은 최소 48px이며 가로 넘침이 없다. Chrome의 실제 터치 이벤트로 일반 목록 스크롤, 길게 누르기, 가장자리 자동 스크롤, 취소를 검증했다. 이름·순서의 새로고침 유지, 작성 중 사진 보존, 삭제된 기본 음료의 재등장 방지, 저장 실패 후 재시도를 확인했다.

테스트 중 발견한 마지막 카테고리의 새 이동 대상 자동 선택 문제와 드래그된 행이 스크롤 높이를 계속 늘리는 문제를 수정했다. 자동 스크롤과 이동 중 행은 드래그 시작 당시 목록 범위를 넘지 않는다.

## 앱 환경 확인 범위

Toss MCP에서 Storage·뒤로가기·iOS 스와이프·BottomSheet 공식 문서를 확인했다. 출처와 기존 연동 방식은 `docs/toss-integration.md`의 Category management 항목에 기록했다. 실제 토스 앱의 Android/iOS QR 기기 검증은 이번 브라우저 테스트에 포함되지 않는다.
