# 문헌 기반 카페인 예측·개인화 개발 프롬프트

아래 내용을 개발 에이전트에게 전달해 실행한다.

---

이 저장소의 카페인 추적 앱에 논문 근거를 갖춘 시간별 잔존량 추정과 사용자 피드백 기반 개인화를 설계하고 구현해줘. 기존 AGENTS.md와 현재 코드를 먼저 읽고 적용해줘. 목표는 복잡한 모델을 만드는 것이 아니라, 현재 수집 가능한 데이터로 검증 가능한 예측 개선을 만드는 것이다.

## 1. 제품 목표와 과학적 경계

- 섭취 기록으로 시간별 추정 잔존 카페인을 계산한다.
- 다음날 앱을 열었을 때 전날의 체감 지속 시간에 관한 짧은 피드백을 받아 사용자에게 맞는 예측을 점진적으로 학습한다.
- 실제 제거 반감기(PK)와 사용자가 느끼는 각성·수면 영향(PD)을 분리한다. 체감이 빨리 사라졌다는 응답을 실제 카페인이 빨리 대사되었다는 관측값으로 취급하지 않는다.
- 자기보고만으로 개인의 생리학적 반감기, 혈중 농도, CYP1A2 활성이나 유전자형을 알아냈다고 주장하지 않는다.
- 홈의 인체·mg는 문헌 기반 잔존량 추정으로 유지한다. 피드백만으로 이 mg를 빨리 없애거나, 체감 점수를 mg로 바꾸지 않는다.
- 피드백에 따라 조절하는 파라미터는 `perceivedDurationAdjustment` 또는 `subjectiveEffectiveDecayHours`처럼 별도 관리한다. 사용자에게는 ‘체감에 맞춘 지속 시간 예측’이라고 설명한다.
- 향후 생리학적 반감기까지 개인화하려면 검증된 시간대별 혈액·타액 농도 등 별도 관측과 연구가 필요함을 설계에 명시한다. 임상 측정을 앱의 일반 사용자에게 요구하지 않는다.
- ‘최고’, ‘정확한 개인 반감기’, ‘안전한 섭취 시각’ 같은 검증되지 않은 표현을 사용하지 않는다.

## 2. 문헌 조사와 근거 관리

카페인 흡수·제거, 개인차, 용량·섭취 간격, 반복 섭취, 각성·수면 반응, 내성·금단에 관한 인간 대상 연구를 조사한다. 체계적 분석으로 전체 지형을 파악하고 모델에 사용하는 수치는 원 연구까지 확인한다.

출발점:

1. Grzegorzewski et al. (2022), Pharmacokinetics of Caffeine: A Systematic Analysis of Reported Data for Application in Metabolic Phenotyping and Liver Function Testing. DOI: 10.3389/fphar.2021.752826. 141개 출판물의 데이터를 통합한 분석이다. 포함·제외 기준과 대상 집단을 확인한다.
2. Fendt et al. (2021), Data-driven personalization of a physiologically based pharmacokinetic model for caffeine: A systematic assessment. DOI: 10.1002/psp4.12646. 실제 개인화에 어떤 관측 자료가 사용되었는지 확인한다.
3. Kaplan et al. (1997), Dose-dependent pharmacokinetics and psychomotor effects of caffeine in humans. DOI: 10.1002/j.1552-4604.1997.tb04356.x. 단순한 선형 제거 가정의 적용 범위와 한계를 검토한다.
4. Drake et al. (2013), Caffeine Effects on Sleep Taken 0, 3, or 6 Hours before Going to Bed. DOI: 10.5664/jcsm.3170. 주관적·객관적 결과를 구분한다.
5. Gardiner et al. (온라인 2024 / SLEEP 2025), Dose and timing effects of caffeine on subsequent sleep: a randomized clinical crossover trial. DOI: 10.1093/sleep/zsae230. 표본과 용량·시각 조건의 일반화 한계를 확인한다.

- 검색일, 검색어, 포함·제외 기준을 남기고 ‘모든 논문을 검토했다’고 주장하지 않는다.
- 각 근거에 표본 수, 대상, 연구 설계, 용량, 측정 결과, 추정치의 분산, 한계를 기록한다.
- 결과가 충돌하면 설명하고 특정 논문의 수치 하나를 전체 사용자에게 그대로 적용하지 않는다.
- 원문을 확보하지 못했으면 초록만 확인했다는 사실을 명시한다. 논문·DOI·결과를 생성하지 않는다.
- 문헌 근거, 통계적 가정, 제품 운영 가정을 분리해서 표시한다. 임의의 학습률·최소 응답 수·보정 한계를 논문 수치처럼 제시하지 않는다.

## 3. 잔존량 추정 모델

현재 1차 제거 모델을 기준 모델로 삼는다.

    remainingMg(t) = Σ doseMg[i] × exp(-ln(2) × elapsedHours[i] / halfLifeHours)

- 아직 섭취하지 않은 미래 기록은 합산하지 않는다.
- 자정에 잔존량을 초기화하지 않는다. 전날과 그 이전 섭취도 계속 기여한다.
- 기본 5시간은 현재 앱의 초기 가정이며 모든 사람의 확정 반감기가 아니다. 이를 유지하거나 바꾸는 근거를 제시한다.
- 단순 모델, 1구획 흡수·제거 모델, 문헌 기반 집단 파라미터 분포 모델을 비교한다. 복잡도를 늘릴 때는 필요한 관측값과 검증 가능한 이점을 설명한다.
- 섭취 직후 전량이 즉시 체내에 분포한다는 근사를 명시한다. 흡수 모델을 채택한다면 초기 흡수 과정과 그 이후 감소를 구분하고 수치적으로 검증한다.
- 체중·흡연·복약·임신 등의 변수를 검토하되 근거 없는 배율을 만들지 않는다. 민감한 입력은 선택 사항으로 최소화하고, 일반 성인 근거를 다른 집단에 자동 적용하지 않는다.
- 음료 카페인량의 sample/official/custom 출처와 함량 오차, 누락 섭취에 따른 불확실성을 고려한다.
- 잔존량의 범위를 제공한다면 파라미터·입력 불확실성에서 계산한다. 근거 없이 ‘95% 정확도’ 또는 ‘95% 신뢰구간’이라고 붙이지 않는다.
- 거의 0인 수치의 표시 기준과 내부 계산을 분리한다. 0mg 표시를 실제 완전 제거로 설명하지 않는다.

## 4. 다음날 체크인 UX

- 전날 기록이 있는 사용자가 다음날 처음 앱을 사용할 때 한 번 제안한다. 홈 이용을 막지 않는 작은 카드에서 시작하고 응답은 선택 사항으로 한다.
- ‘어제 반감기가 빨랐나요?’ 대신 관측 가능한 체감에 관해 묻는다.
- 전날 사전 예측을 보여준 경우: ‘어제 예상한 시간과 비교해 카페인으로 느낀 각성감은 어땠나요?’
  - 예상보다 일찍 줄었어요
  - 대체로 비슷했어요
  - 예상보다 오래 갔어요
  - 잘 모르겠어요
- 비교 대상인 전날 예측 시간대와 마지막 섭취 시각을 명확하게 표시한다. 사전 예측이 없었다면 ‘일치 여부’를 묻거나 학습 정답으로 만들지 않는다.
- 처음에는 선택적으로 ‘대략 언제 각성감이 줄었는지’를 시간대 또는 구간으로 받는다. 몰랐다는 응답을 허용하고, 측정할 수 없는 ‘절반이 제거된 시각’은 묻지 않는다.
- 앵커링을 줄이기 위해 가능한 경우 체감 시각을 먼저 받고 이전 예측은 그 후 비교한다. 이 순서도 검증할 UX 가정으로 기록한다.
- 필요할 때만 수면 부족·스트레스·음주·미기록 섭취 같은 최소 맥락을 추가로 받는다. 수면 피드백은 각성 지속 피드백과 별도 결과변수로 관리한다.
- ‘잘 모르겠어요’, 미응답, 건너뛰기는 일치 응답이 아니며 파라미터 갱신에서 제외한다.
- 이미 응답한 날짜에는 다시 묻지 않는다. 같은 날 닫은 체크인을 앱을 열 때마다 반복하지 않는다.
- 여러 날 뒤 복귀하면 설문을 연달아 띄우지 않는다. 회상 기간 정책을 명시하고 오래된 기억을 정밀한 관측으로 사용하지 않는다.
- 야간 섭취·자정 이후 취침을 고려해 섭취일, 실제 피드백 대상 구간, 응답일을 별도 저장한다. 날짜가 바뀌었다고 아직 끝나지 않은 체감 구간을 종료로 처리하지 않는다.

## 5. 개인화 학습 알고리즘

문헌 기반 잔존량 계산을 입력 특성으로 사용할 수 있지만, 자기보고 학습의 목적변수는 체감 지속 시간으로 한정한다.

- 기준 모델과 개인화 후보를 먼저 정의한다. 희소한 개인 기록에는 사전값으로 수축하는 규제 모델 또는 계층적 베이지안 접근을 우선 검토한다.
- 한 사람의 소수 응답으로 제거율·흡수율·민감도·내성을 동시에 추정하지 않는다. 처음에는 식별 가능한 소수의 체감 보정 변수만 사용한다.
- 시각 구간 응답은 구간 관측으로 취급한다. ‘빠름/비슷함/늦음’ 응답에는 순서형 관측 모델 등 그 정보량에 맞는 손실·우도를 사용한다. 비교 응답 하나를 정확한 종료 시각으로 변환하지 않는다.
- ‘일찍 줄었다’는 신뢰할 수 있는 응답이 반복되면 체감 지속 예측이 짧아지는 방향, ‘오래 갔다’가 반복되면 길어지는 방향으로 점진적으로 조정한다. ‘비슷함’은 일치 구간에 대한 약한 관측으로 취급하고, 무응답은 갱신하지 않는다.
- 학습률, 관측 가중치, 사전분포, 보정 범위, 1회·누적 변경 한계, 보류 조건, 되돌리기 조건을 수식·의사코드·설정값으로 명확하게 제시한다.
- 그 수치가 연구로 정해지지 않았다면 제품 가정이라고 표시하고 민감도 분석을 한다. ‘응답 7개면 정확’ 같은 보장 기준을 만들지 않는다.
- 기록 누락, 불명확한 체감, 추가 섭취, 상충되는 응답, 큰 교란이 있으면 관측의 가중치를 낮추거나 갱신을 보류한다. 모순된 응답이 늘었는데 확신도가 계속 높아져서는 안 된다.
- 충분한 근거가 없으면 기본 예측을 유지한다. 단순히 날짜가 지났거나 응답 수가 늘었다고 정확도가 높아졌다고 표시하지 않는다.
- 과거 관측을 잊는 전략이나 최근 가중치를 쓰면 생활 패턴 변화와 일시적 잡음을 어떻게 구분할지 설명한다.
- 사용자에게 개인화 적용 여부, 사용한 유효 응답 수, 기본값 복원과 학습 초기화를 제공한다.
- 검증 전 개인화는 ‘실험적 체감 예측’으로 표시한다. 데이터가 부족하면 알고리즘 구현과 예측 성능 검증의 완료 여부를 구분한다.

## 6. 데이터와 기존 프로젝트 통합

- React·TypeScript·Vite 구조를 유지하고 불필요한 ML 라이브러리나 서버를 추가하지 않는다.
- PK 계산, 체감 보정, 체크인 노출 정책, UI, 저장소를 분리한다. UI가 localStorage에 직접 접근하지 않는다.
- 순수 함수에 현재 시각을 주입하고 테스트에서 시간을 고정할 수 있게 한다.
- 기존 수동 half-life 설정은 ‘기본 추정 모델의 설정’으로 구분한다. 체감 개인화가 이 값을 몰래 덮어쓰지 않는다.
- 기존 홈의 인체 중심 구성, 기록 캘린더, 미래 날짜 숨김, Bottom Sheet와 뒤로가기 동작을 보존한다.
- 노출 당시의 predictionId, modelVersion, parameterVersion, 예측 생성 시각, 대상 시간 구간, 섭취 기록 버전, 예측값을 스냅샷으로 저장한다.
- 피드백에는 대상 날짜·시간대, answer, observedInterval, 선택적 맥락, 응답 시각, predictionId를 저장한다.
- 갱신 이벤트에는 이전·이후 파라미터, 사용한 피드백, 가중치, 변경·보류 이유를 저장해 설명하고 재현할 수 있게 한다.
- 동일 피드백을 중복 학습하지 않게 한다. 사용자 시간대 변경과 자정 경계를 처리하고, 누락값을 0이나 ‘일치’로 보정하지 않는다.
- 섭취 기록이나 피드백을 수정·삭제하면 학습 기여를 제거하거나 원본 이벤트에서 재학습한다. 과거 예측 스냅샷은 당시 기록으로 남기고, 수정된 데이터와 불일치하면 평가에서 구분한다.
- 버전 있는 저장소 마이그레이션으로 기존 기록·음료·설정을 유지한다. 개인화 초기화와 전체 데이터 삭제를 구분한다.
- 개인 기록을 외부 모델이나 서버로 전송하는 구조는 기본값에 넣지 않는다. Apps in Toss API를 변경할 때는 최신 공식 문서를 확인한다.

## 7. 검증 기준

수학·동작 테스트:
- 같은 복용량이 설정한 반감기 후 절반이 되는지, 여러 복용량이 합산되는지, 자정에도 연속적인지 검증한다.
- 흡수 없는 모델은 추가 섭취가 없을 때 감소해야 한다. 흡수 모델에서는 흡수 단계의 증가를 잘못된 동작으로 판정하지 않는다.
- 빈 기록, 0mg, 누락·잘못된 날짜, 미래 기록, 수치적 오버플로를 처리한다.
- 빠름·늦음의 반복 응답, 교대 응답, 결측, 같은 피드백 재전송, 데이터 수정·삭제, 장기 공백, 시간대 변경을 검증한다.
- 잘 모르겠어요·건너뛰기·미응답이 모델을 바꾸지 않는지 확인한다.
- 체크인 중복 노출 방지, 기본값 복원, 학습 초기화, 저장 실패·마이그레이션을 검증한다.

예측 성능 검증:
- 동일 사용자 데이터를 시간순으로 나누고 미래 응답을 이전 예측에 사용하지 않는다.
- ‘예측 → 관측 → 평가 → 학습’ 순서를 지킨다. 업데이트한 모델로 과거 예측을 다시 만들어 좋은 점수를 내지 않는다.
- 고정 기준 모델, 단순 보정 모델, 최종 후보를 비교한다. 실제 관측 형태에 맞는 오차·로그 손실·보정도와 불확실성을 제시한다.
- 가능하면 모델이 제시한 예측에 영향을 덜 받은 실제 체감 시간 구간을 평가에 사용한다. 주관적인 ‘맞았어요’ 비율만으로 성능을 확정하지 않는다.
- 개인별·시간순 검증에서 개선되지 않거나 악화되면 개인화 적용을 보류하거나 기본 모델로 복귀한다.
- 합성 데이터는 경계 동작 검증에 사용하고 실제 사용자 예측 정확도의 증거로 제시하지 않는다.
- 체감 예측의 성능을 잔존 mg 또는 생리학적 반감기의 정확도로 바꿔 설명하지 않는다.

실행 검증:
- npm run lint, npm test, npm run build 및 기존 E2E를 실행한다.
- 375px·390px에서 체크인 접근성, 텍스트 확대, 라이트·다크 테마, 기본 기록 흐름을 검증한다.

## 8. 작업 순서와 산출물

먼저 문헌 근거와 현재 수집 가능한 데이터가 뒷받침하는 범위를 정리한다. 이어 후보 모델의 식별 가능성·복잡도·검증 방법을 비교하고 권장안을 선택한다. 사용자 의도와 기존 프로젝트 지침에 맞춰 설계·구현·테스트를 진행한다.

산출물:
1. 출처와 한계가 포함된 문헌 근거표.
2. PK 추정과 체감 개인화를 분리한 설계, 수식·업데이트 규칙·파라미터 근거.
3. 짧은 다음날 체크인 UI와 모델 설명 문구.
4. 모델·피드백·버전·마이그레이션·초기화 구현.
5. 자동 테스트 결과와 실제 데이터 검증 계획.
6. 구현 완료, 동작 검증 완료, 예측 성능 미검증을 구분한 최종 보고.

임상적으로 확인하지 못한 개인 반감기를 그럴듯한 숫자로 만드는 것보다, 현재 근거로 말할 수 있는 범위와 실제 개선 여부를 명확하게 보여주는 것을 우선해줘.
