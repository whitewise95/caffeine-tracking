## 포함한 변경

- 모자·안경·상의·하의·신발·소품을 각각 50개로 확장한 300개 아바타 아이템.
- 젤리 몸의 곡면을 감싸는 상·하의 실루엣, 입체 명암과 앞뒤 레이어, 컵을 든 팔의 소매 연결 개선.
- 홈에서 저장된 코디를 잠시 숨겼다가 그대로 복원하는 `겉멋 끄기`.
- 꾸미기에서 선택된 아이템을 다시 누르면 해당 슬롯만 벗는 토글 동작.
- 오늘 기록인 마지막 섭취는 날짜를 생략하고, 이전 날짜일 때만 날짜 표시.
- 시간 휠의 숫자 탭과 키보드 조작, 안내 문구를 제거하고 터치·마우스 세로 드래그로만 값을 변경하도록 단순화.
- 시간 휠의 네이티브 스크롤·CSS 스냅·JS 관성 중복 제어를 제거하고, 한 프레임에 한 번 갱신하는 이동 트랙으로 통일. 비스듬한 터치를 가로 스크롤이 가져가지 않도록 하고, 터치 종료 누락·앱 전환 후에도 다음 드래그에서 복구.
- 선택값 변경 시 Toss의 약한 `tickWeak` 햅틱을 제공하되 최소 50ms 간격 및 응답 대기 중 중복 요청 제한을 적용. 늦어진 진동을 줄 세우지 않고 생략하며, 실패·1초 이상 미응답 후 새 입력에서 재시도. 이 간격은 앱 자체 정책이고 SDK 공식 제한은 아님. 초기 표시·크기 동기화에는 진동하지 않음.
- 비상호작용 요소로 바꾼 시간 휠의 오전·오후와 숫자 레이블을 각 선택 칸의 가로·세로 중앙에 명시적으로 정렬. '동작 줄이기'에서도 첫 프레임부터 선택값과 휠 위치가 일치하도록 불필요한 CSS 이동 전환을 차단.
- 꾸미기 적용 버튼에 `AD` 표기를 추가하고, 저장 성공 후 전면 광고 그룹 `ait.v2.live.cf69107c15014790`을 노출. 광고 미지원·미로딩·표시 실패 시에는 저장과 화면 이동을 그대로 진행.
- 기존 카페인 계산, 액체 높이, 표정, 기록과 저장 데이터 호환성 유지.

## 검증과 재빌드

업로드 전 ESLint, 단위 테스트 497개, TypeScript·Vite·AIT 빌드를 통과했다. 마지막 시간 선택·햅틱·취침 시각 E2E 실행에서 Chromium 375px·390px 및 WebKit 390px 기준 74개를 통과했다. Chromium 전용 네이티브 터치 입력 3개는 WebKit에서 제외하며 Chromium 두 화면 크기에서 통과했다. 별도 실행한 기록·섭취 모드·시간 범위·전날 섭취 관련 E2E 46개도 통과했다.

Toss 호스트를 모사한 테스트에서 느리거나 실패한 햅틱 응답에도 드래그가 계속되고 이전 진동이 뒤늦게 쌓여 나오지 않는 것을 확인했다. 크기 동기화 시 무진동, 첫 표시 및 확대 글자의 중앙 정렬도 검증했다. 프로덕션 번들에는 라이브 광고 그룹 ID만 포함되고 개발·자동 테스트에서는 공식 전면 광고 테스트 ID를 사용한다. 실제 진동의 세기와 아이폰 토스 앱의 동작은 기기 테스트에서 확인해야 한다.

```bash
npm run lint
npm test
npm run build:toss
```

새로 빌드하면 deploymentId와 번들 해시가 바뀔 수 있다. 위 값은 현재 업로드를 위해 준비한 파일의 값이다. 테스트 절차는 [앱인토스 공식 가이드](https://developers-apps-in-toss.toss.im/guide/operation/toss)를 따른다.

## 아이폰 WebView 회귀 확인

이전 구현에서 가로로 20px, 세로로 2px 움직인 뒤 위로 드래그하면 `pan-x`가 터치를 가져가 `pointercancel`이 발생하고 선택값이 바뀌지 않는 현상을 Chromium 네이티브 터치 입력으로 재현했다. 터치 종료 이벤트가 누락된 후 새 드래그를 무시하는 현상도 이벤트 누락 시나리오로 재현했다. 수정 후 두 경우 모두 값 변경과 중앙 정렬을 확인한다.

드래그 중 행 크기 측정을 반복하지 않고, 스크롤 위치 재측정 없이 `transform`만 갱신한다. WebKit에서도 드래그·관성·취소·창 포커스 이탈 복구·확대 글자·양축 정렬·느린/실패한 햅틱 응답을 검사한다. WebKit 자동화는 실제 아이폰 토스 앱이 아니므로, 브리지 지연과 실제 진동 감각은 이 번들을 올린 뒤 기기에서 추가 확인해야 한다.

기기 확인: 시작/종료 시각에서 비스듬한 드래그, 빠른 왕복 드래그, 한 칸씩 느린 드래그, 앱 전환 후 재조작을 확인한다. 진동이 늦게 몰려 나오지 않고, 선택한 값이 완료 후 저장되는지도 확인한다.
