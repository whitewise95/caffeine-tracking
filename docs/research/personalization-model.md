# 체감 지속 시간 개인화 모델 v1

> 현재 제품 화면에서는 체감 지속 시간 예측을 노출하지 않는다. 매일의 질문은 체감 기록용이며 남긴 응답은 설정에서 확인·수정·삭제한다. 아래 예측·보정 엔진과 과거 스냅샷은 기존 데이터 호환성을 위해 보존하며, 새 UI에서 예측 노출 스냅샷을 생성하지 않는다. 현재 화면 검증은 [체감 기록 검증](../verification-feeling-journal.md)을 참고한다.

2026-10-04 구현 설계. 문헌표는 [caffeine-evidence.md](./caffeine-evidence.md)를 참고한다. 현재 기본 입력은 매일 세 가지 선택지로 받는 **실험적 체감 보정**이다. 이 규칙은 인용 문헌에서 임상 검증한 알고리즘이 아니며, 응답을 적용했다는 사실이 예측 성능 개선을 뜻하지 않는다. 기존 사전 예측 비교·시간 구간 자료는 별도 평가 경로로 보존한다.

## 모델의 경계

- 홈의 잔존 mg는 기존 다중 섭취 1차 제거식으로 계산한다. 기본 제거 반감기 **5시간을 고정**하며, 사용자 설정이나 체감 학습이 이를 바꾸지 않는다.
- 이 모듈은 잔존 mg, 실제 제거 반감기, 혈중 농도를 입력·출력하지 않는다. 별도 체감 지속 시간 보정 θ만 학습한다.
- 기준 체감 지속 시간 6시간, 표시 구간 ±1시간은 **제품 운영 가정**이다. 논문에서 도출한 일반인의 각성 지속 시간 또는 신뢰구간이 아니다. 섭취량·민감도·내성을 동시에 추정하지 않으며, 음료 종류·용량에 따른 일반화 능력도 주장하지 않는다.
- `sourceType`은 sample/official/custom 출처의 이력 및 변경 감지에 사용한다. 출처별 함량 오차 분포나 약리학적 배율을 도입하지 않는다.

## 수식과 보정 규칙

마지막 섭취 후 예상 체감 시간은 μ = 6 + θ (시간)다. θ는 -3~+6시간으로 제한한다. 이것은 제거 반감기와 다른 변수다.

### 현재 기본 입력: 일일 체감 방향

`responseKind: 'daily-feeling'` 응답은 이전 예측과 비교한 관측이 아니라 사용자가 요청한 방향의 작은 보정이다. `predictionId`와 관측 종료 구간을 저장하지 않는다.

| 답변 의미 | 저장 값 | 적용 |
| --- | --- | --- |
| 더 오래 느껴짐 | `later` | θ + 0.25시간 |
| 평소와 비슷함 | `similar` | θ를 정확히 유지 |
| 더 짧게 느껴짐 | `earlier` | θ − 0.25시간 |

매번 [-3,+6]시간 한계를 적용한다. 가운데 답변에는 수축·평균 회귀를 적용하지 않는다. 교대로 답해도 그 자체를 정확도 오류나 모순으로 판정하지 않는다. 실제 효과가 끝나기 전에 답할 수 있으므로 완료된 체감 시간 관측으로 해석하지 않는다. 응답이 유효하면 사전 평가 3개를 기다리지 않고 `self-reported` 상태에서 이후 체감 예측에 보정값을 적용한다. 이 상태의 문구는 정확도가 아직 검증되지 않은 실험적 보정이라고 명시한다. 시간대·장기 공백 보류는 유지한다. 최근 유효한 일일 응답이 있으면 과거 예측 비교에서 발생한 모순·성능 악화 보류가 새 수동 보정을 막지 않는다. 과거 평가 수치는 이력으로 보존하며 일일 보정의 성능 증거로 사용하지 않는다.

### 기존 자료: 시간 구간과 예측 대비 순서형 응답

절대 시각 구간 [a,b]는 마지막 섭취로부터의 경과 시간으로 변환한다. 구간 손실은 `L = 0.5 × distance(μ,[a,b])²`, 기울기는 `g = μ - clamp(μ,a,b)`다. 예측이 구간 안에 있으면 관측 기울기는 0이다. 실제 종료 시각을 구간 중간값으로 만들어 최종 후보에 넣지 않는다.

순서형 응답은 **당시 실제 보여준 구간** [l,u]에 대한 logistic 잠재 시간 관측이다. `F(x) = sigmoid((x-μ)/s)`, s=1.5시간이다.

- 일찍: `P(Y<l) = F(l)`, 음의 로그우도 기울기 `(1-F(l))/s`
- 오래: `P(Y>u) = 1-F(u)`, 기울기 `-F(u)/s`
- 비슷: `P(l≤Y≤u) = F(u)-F(l)`, 기울기 `[F(u)(1-F(u))-F(l)(1-F(l))] / [s(F(u)-F(l))]`

`비슷`의 관측 가중치 w=0.25, 나머지 유효 관측은 w=1이다. L2 사전값 수축을 포함해 다음처럼 갱신한다.

```
rawDelta = -0.5 × (w × g + 0.05 × θ)
delta = clamp(rawDelta, -0.25, +0.25)
newTheta = clamp(θ + delta, -3, +6)
```

개별 유효 응답의 갱신은 최대 15분이다. 원본 기록 수정·삭제로 재학습하거나 보류 상태가 되면 잘못된 기존 기여를 한 번에 제거할 수 있다. 이때의 제거는 새 관측을 크게 학습한 것이 아니다. 모든 숫자는 운영 가정이며 아래 민감도 검사는 경계 동작만 검증한다.

## 체크인·보류 정책

- 기기 시간대를 포함한 섭취일·응답일·구간을 분리한다. 순수 함수에 `now`를 주입하며, 원본 ISO 시각의 시간대 오프셋을 UTC로 정규화한다.
- 개인화가 켜져 있고 기기 현지 날짜 기준 **전날에 양수 섭취 기록이 있으며 아직 답변하지 않은 경우** 앱 진입 시 팝업을 제안한다. 마지막 섭취 후 13시간 대기는 적용하지 않는다. 오늘과 그저께 기록만 있는 경우에는 제안하지 않는다. 이는 질문 노출 조건이며 체감 구간 종료를 의미하지 않는다.
- 사용자가 명시적으로 예측 보기 동작을 한 시점에만 새 예측을 저장한다. 기준·후보·단순 평균 모두의 예측 구간 시작이 아직 미래일 때만 생성한다.
- 일일 체감 세 가지 응답은 과거 예측 없이 받는다. 기존 `responseKind`가 없는 순서형 비교 응답은 여전히 과거 예측이 필요하며, 이를 새 일일 자기보고로 소급 변경하지 않는다.
- 절대 구간의 최대 폭은 4시간, 섭취 이후 최대 24시간으로 제한한다. 이 역시 입력 품질을 위한 가정이다.
- 답변한 날짜·시간대와 이미 처리한 마지막 섭취는 재질문하지 않는다. 여행으로 시간대가 달라져도 같은 마지막 섭취를 반복 질문하지 않는다. 팝업 닫기는 현재 앱 세션에서만 숨기며 답변으로 저장하지 않는다. 예전에 저장한 `skipped`도 미응답으로 취급하고, 실제 답변 제출 시 같은 날짜의 건너뛰기 레코드를 교체한다. 기존 모르겠음·건너뛰기·교란 자료는 보정하지 않는다.
- 일일 응답의 원본 스냅샷은 대상 날짜의 마지막 섭취 시각까지만 포함한다. 다음 날 새로 마신 음료는 이 응답을 무효화하지 않는다. 대상 날짜 기록을 수정·삭제하거나 늦은 섭취를 추가한 경우에는 기존 기여를 제외한다.
- 기존 시간 구간·예측 비교 응답에서는 마지막 대상 섭취 이후 관측 구간 안에 추가 섭취가 있으면 학습에서 제외한다. 최근 방향 있는 4개 비교 관측 중 방향 전환이 2회 이상이면 해당 갱신을 보류한다. 최근 4개 갱신 이력에 이런 충돌이 남아 있고 현재 유효한 일일 보정이 없다면 적용도 보류한다. 일일 방향 응답에는 이 모순 판정을 적용하지 않는다. 확신도나 정확도 백분율은 표시하지 않는다.
- 유효 학습 응답이 **14일 넘게 끊기면** 기본 예측으로 돌아간다. 다음 유효 응답은 새 학습 구간(episode)을 시작하며 예전 보정이 다시 튀어나오지 않는다. 매일 응답하는 경우 14일마다 과거 관측을 삭제하지 않는다. 따라서 장기간 연속 사용 중 완만한 생활 패턴 변화에 대한 별도 망각 모델은 구현하지 않았다.
- 시간대가 달라진 응답은 현재 시간대 학습에 사용하지 않는다. 현재 시간대와 최근 응답 시간대가 다르면 적용을 보류한다. 시간대 이동을 대사 변화로 해석하지 않는다.

## 시간순 평가와 적용 조건

기존 시간 구간 평가에서는 예측 → 사용자의 관측 → 저장된 예측 평가 → 학습 순서를 고정한다. **일일 방향 응답은 이 정량 평가에 포함하지 않는다.** `PredictionSnapshot`에는 당시 기준/후보/단순 모델의 값, 실제 표시 값, 파라미터, 모델·파라미터 버전, 시각·시간대, 섭취 원본과 출처, 학습 이력 지문을 저장한다.

평가에는 아래를 모두 만족하는 절대 구간만 사용한다.

1. 실제 사전 노출된 예측이 있고, 생성 시각이 관측 구간 시작보다 이르다.
2. 체크인에서 과거 예측을 다시 보여주기 전에 구간을 입력했다는 `observedWithoutComparison=true`가 있다.
3. 교란·원본 변경·시간대 불일치가 없고, 나중에 수정한 피드백이 아니다.
4. 해당 예측을 학습시킨 이력의 지문이 일치한다. 삭제·수정한 기여를 사용했던 예측은 평가에서 제외한다.

전날 보았던 예측의 앵커링까지 제거할 수 없으므로 이는 독립적인 임상 평가가 아니다. 순서형 ‘맞았어요’는 적용 성능의 정답으로 사용하지 않는다.

오차는 예측 시간에서 관측 구간까지의 절대 거리(시간)다. 최근 최대 8개 유효 사전 평가에서 기준·후보·단순 모델을 같은 라벨로 비교한다. 일일 방향 자료가 없는 기존 경로에서는 **최소 3개** 평가가 있고 후보 평균 오차가 기준보다 **0.25시간 이상 작고**, 다른 보류 이유가 없을 때만 `active` 상태로 후보를 표시한다. 두 숫자는 실험용 운영 문턱이지 정확성 보장이나 통계적 유의성 기준이 아니다. 후보가 단순 평균보다 우수하다고 주장하지 않는다. 기존 평가에서 후보가 기준보다 나빠지고 현재 유효한 일일 보정이 없다면 기본 예측으로 돌아간다. 일일 방향 보정의 `self-reported` 상태는 이 검증을 통과했다는 뜻이 아니다.

과거 예측은 다시 만들지 않는다. 현재 화면에서는 삭제·수정한 학습 이력이 들어간 오래된 예측을 감추고, 아직 미래 예측이 가능한 경우에만 새로 보기 동작으로 재생성한다.

## 저장·복구·성능

- Repository에서 엄격한 중첩 타입·시간·수치·enum·중복 ID 검증을 사용한다. 예측 원본, 피드백 원본, 응답 수정 시각, 재학습 감사 이력을 보존한다.
- 동일 날짜 제출은 멱등적이다. 피드백 수정은 원래 대상·응답 종류·원본 섭취 스냅샷을 유지하고 기여를 재계산한다. 수정 라벨은 사전 평가에서 제외한다. 저장 버전과 기존 응답의 학습 지문은 유지하며 일일 응답만 지문에 종류를 추가한다.
- 기본값 복원은 기능을 끄면서 기록을 보존한다. 학습 초기화는 예측·응답·감사 이력을 지우고 보정값을 초기화한다. 전체 카페인 기록 삭제와 구분한다.
- 기기 내에서만 계산하며 외부 ML 서비스로 전송하지 않는다.
- 시간대별 날짜 포매터를 최대 8개 캐시하고, 재생 때 섭취 시각·날짜를 한 번만 정규화한다. 학습 지문은 두 결정적 32-bit 체크섬과 관측 수로 저장해 매 예측에 전체 이전 학습 내용을 중복 저장하지 않는다. 인증용 해시가 아니며 희박한 충돌 가능성은 남는다. 재생 중에는 누적 지문을 사용한다.

## 검증 상태

자동 테스트는 자정 직후 전날 질문, 무기록·답변 완료 제외, 기존 건너뛰기 교체, 예측 없는 세 가지 응답, 0이 아닌 보정의 정확한 유지, 다음 날 섭취 분리, 저장 검증, 원본·응답 수정/삭제 재생을 검증한다. 기존 순서형 방향, 구간 관측, 사전 평가, 무응답·교란, 시간대, ISO 오프셋, 미래/사후 예측 방지, 멱등성, 장기 공백 복귀, 연속 40일 사용 검사도 유지한다. 경계 동작 통과가 실제 사용자 예측 정확도를 입증하지 않는다.

민감도 검사와 365일 재생 계측 결과는 아래에 별도로 기록한다. 긴 계측은 기본 테스트에서 제외하고 `RUN_PERSONALIZATION_BENCHMARK=1 npm test -- src/features/personalization/model/personalization.test.ts`로 실행한다.

### 실제 실행한 합성 민감도 검사

12회 반복한 절대 구간을 사용했다. 긴 경우 [8,9]시간, 짧은 경우 [3,4]시간, 교대하는 경우 두 구간을 번갈아 넣었다. 아래는 **θ의 최종 값(시간)**이며 사용자 예측 정확도가 아니다. 실제 체크인 모듈의 모순 보류 이전에 적용되는 수치 갱신 함수를 대상으로 파라미터 민감도를 확인했다.

| 학습률 / 수축 / 1회 한계 | 긴 구간 반복 | 짧은 구간 반복 | 교대 구간 |
| --- | ---: | ---: | ---: |
| 0.25 / 0.10 / 0.125h | +1.496875 | -1.496875 | 0 |
| **0.50 / 0.05 / 0.250h (기본)** | **+1.900113** | **-1.900113** | **0** |
| 0.75 / 0.025 / 0.500h | +1.951219 | -1.951219 | 0 |

모든 변형에서 방향과 1회 변경 상한을 검사했다. 이 실험에서 기본값이 통계적으로 최적이라는 결론을 낼 수는 없다. 더 느린 설정은 같은 반복 횟수에서 변화가 적고, 더 빠른 설정은 일시적 응답의 영향도 더 클 수 있다. 실제 사용자에서 보정된 평균 오차·순서형 로그손실·하위 집단별 성능을 검증하는 후속 연구가 필요하다.

### 로컬 재생 계측

개발 환경 Node/Vitest에서 합성 **365일, 730개 섭취, 365개 응답**을 생성한 뒤 재생 한 번을 측정했다. 재생 약 **14.26ms**, 개인화 상태 JSON의 UTF-8 크기 **660,767바이트**였다. 테스트 데이터 생성과 전체 검증에는 약 8초가 걸렸다. 기기 WebView, 장기 저장 용량, 실제 사용 속도에 대한 보장 수치가 아니다. 저장에는 카페인 기록 원본 등 다른 상태도 추가되며 전체 데이터 용량은 별도로 관리해야 한다.

위 계측 당시 모델 테스트 25개가 통과했다. 일일 응답 및 과거 보류 이력 호환성 추가 후 일반 실행의 모델 테스트 35개가 통과했다. 긴 계측은 일반 실행에 포함하지 않으며 이번 UI 단순화에서는 다시 수행하지 않았다. 실제 사용자 자료에 대한 예측 성능 검증은 아직 수행하지 않았다.
