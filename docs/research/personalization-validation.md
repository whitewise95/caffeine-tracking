# 체감 개인화의 실제 사용자 검증 계획

> 보관 문서: 2026-10-04 사용자 요청에 따라 관련 UI·설문·보정 로직을 제거했습니다. 현재 앱은 기본 반감기 4시간 30분을 사용합니다(2026-10-05 변경). 아래의 5시간 기준과 검증 결과는 당시 설계 또는 추후 검토 자료로 보존합니다.


작성일: 2026-10-04. 이 문서는 **향후 검증 프로토콜 제안**이다. 모집·사용자 연구·외부 전송은 실행하지 않았다. 합성 데이터나 자동 테스트 통과가 실제 사용자의 체감 예측 정확도를 증명하지 않는다. 과학적 배경과 문헌 접근 한계는 [근거 문서](caffeine-evidence.md)에 따로 기록했다.

## 검증 대상과 주장 범위

목표변수는 사용자가 인지한 각성감이 줄어든 시각 또는 그 구간이다. 수면 질·잠드는 시각·생리학적 제거 반감기·혈중 농도·잔존 mg의 정확도는 별도 결과이며 이 검증으로 추론하지 않는다. 비교 응답에 '비슷했어요'가 많아졌다는 이유로 생리학적 정확도를 주장하지 않는다.

현재 구현은 마지막 섭취 후 고정 체감 prior와 작은 시간 보정값을 사용하는 실험적 후보다. 기본 6시간 체감 prior, 구간 폭, 학습률, 최소 평가 수, 개선 기준, 보정 한계는 운영 가정이다. PK의 고정 5시간과 별개이며 두 숫자가 생리학적으로 같은 의미를 가진다고 설명하지 않는다.

현재 기본 팝업의 세 가지 선택지는 `responseKind: 'daily-feeling'`인 일일 방향 자기보고다. 오래/평소와 비슷/짧게 느낌에 따라 체감 시간 보정값을 +15분/유지/−15분 조정한다. 이전 예측을 보지 않아도 답할 수 있고 자정 직후에도 나타나므로, 예측 대비 오차나 완료된 체감 종료 관측으로 사용하지 않는다. `self-reported` 적용 상태는 **실험적 수동 보정**을 의미하며 성능 검증 통과를 의미하지 않는다. 이 응답만으로 아래 시간 구간 평가를 수행할 수 없다.

## 사전 고정할 항목

실제 연구에 앞서 대상 집단, 모집/동의 절차, 주요 결과, 분석 제외 기준, 모델 버전, 하이퍼파라미터, 최소 의미 있는 개선량, 평가 기간, 표본 설계와 종료 조건을 고정한다. 참가자 수는 목표 효과와 사용자 내 상관을 고려한 사전 검정력 또는 추정 정밀도 설계로 정한다. 앱의 '평가 3개'와 같은 활성화 조건은 통계적 충분성이나 검정력을 보장하지 않는다.

데이터 최소화 원칙에 따라 일반 앱의 로컬 보관과 연구용 자료 수집을 구분한다. 연구용 내보내기·원격 전송·웨어러블 연동을 이 문서만으로 활성화하지 않는다. 선택적 응답, 철회, 자료 삭제 및 보존 기간을 명확히 안내한다.

## 시간순 평가

1. 사용자별로 당시 이용 가능한 섭취·응답만 사용해 기본 모델, 단순 보정 비교 모델, 최종 후보의 예측을 **같은 시각**에 생성한다. 모델·파라미터·학습 이력 버전과 예측값을 동결한다.
2. 예측 생성 이후의 관측만 평가한다. 실제 관측 구간 시작이 생성 시각보다 이르면 해당 결과는 사전 예측 평가에서 제외한다. 미래 응답이나 나중에 수정된 섭취 기록을 과거 예측에 넣지 않는다.
3. 관측이 확보되면 동결된 예측을 평가한 다음 학습한다. 학습 후 과거 예측값을 바꿔 점수를 다시 매기지 않는다.
4. 사용자별 초기 구간은 개발/보정, 이후 연속 구간은 검증에 사용한다. 날짜를 무작위로 섞지 않는다. 여러 사용자로 공통 상수를 고를 때는 사용자를 분리한 외부 검증도 추가한다.
5. 섭취·응답의 수정/삭제는 학습 replay에 반영한다. 당시 학습 이력과 불일치하게 된 후속 예측은 별도 분류한다. 제거된 기여를 사용했던 예측을 수정된 자료에 대한 깨끗한 검증으로 재활용하지 않는다.

장기간 기록한 사용자가 전체 점수를 지배하지 않게 사용자별 점수를 먼저 계산하고 같은 가중치로 집계한 결과를 주요 결과로 삼는다. 관측 수로 가중한 결과는 보조로 표시한다. 사용자별 개선/악화 분포도 제시한다.

## 비교 모델과 오차

| 관측 | 기본·단순·개인화 비교 방법 | 해석 제한 |
| --- | --- | --- |
| 독립적으로 기록한 시간 구간 `[L,U]` | 점 예측 `p`에 대해 `max(L−p, 0, p−U)` 시간의 구간 거리. 같은 관측에서 세 모델을 비교하고 평균/중앙값을 함께 제시 | 구간 안의 어느 시각이 참값인지 모르므로 0점이 정확한 시각 일치를 뜻하지 않음. 넓은 구간이 쉽게 0점이 되는 편향 때문에 구간 폭별 결과·관측 폭 분포를 병기 |
| 확률분포가 있는 시간 예측 | 사전 고정한 관측 오차 모형 아래 구간 확률과 로그 손실, 구간 포함률/폭을 평가 | 확률모형과 검증 없이 화면 범위를 95% 구간이라고 부르지 않음 |
| earlier/similar/later | 실제 보여준 예측 구간의 양 끝을 공통 절단점으로 고정한 순서형 확률의 로그 손실 또는 Brier 점수. 모델별로 자기에게 유리한 절단점을 바꾸지 않음 | 선택지 응답을 종료 시각으로 치환하거나 interval 오차와 평균내지 않음. 모델이 만든 비교 기준에 의존하므로 별도 보조 결과 |
| `daily-feeling`의 earlier/similar/later | 방향에 따른 보정 요청만 기록. 예측 오차·로그 손실·정답값을 부여하지 않음 | 사전 비교 기준도 종료 시각도 없는 일일 자기보고이므로 위 예측 대비 순서형 응답과 구분 |
| 모르겠음·건너뜀·미응답 | 예측 오차/정답값을 부여하지 않고 응답률·사유·시각별 분포를 따로 기록 | missing을 '비슷함'이나 0 오차로 대체하지 않음 |

단순 비교 모델은 이전 관측만으로 만든 명시적 시간 보정 모델로 고정한다. 구간 중간값 평균을 단순 기준에 사용하더라도 중간값이 실제 관측된 종료 시각이라고 주장하지 않는다. 최종 후보가 고정 prior보다 좋아도 단순 기준보다 좋은지 별도 비교한다.

## 앵커링·누락·교란

기존 시간 구간 입력 UI에서는 체감 시각을 먼저 받은 후 예측을 비교하게 하여 **체크인 도중의 추가 앵커링**을 줄이려 했다. 사용자가 전날 예측을 이미 보았다는 영향까지 제거하지 못한다. 과거 자료의 `observedWithoutComparison`은 이번 응답 입력 전에 체크인 비교를 펼쳤는지에 관한 플래그이며 관측의 완전한 독립성 증명이 아니다. 현재 단순 팝업은 이 플래그나 종료 시간 구간을 수집하지 않는다.

강한 성능 검증에는 별도 동의를 받은 연구에서 예측을 숨긴 shadow 평가나 노출 시점을 무작위 배정하는 설계를 고려한다. 숨긴 예측도 결과 전에 동결하며, 예측 노출 여부에 따른 응답 변화 자체도 분석한다. 현재 앱이 이러한 연구를 수행하거나 독립 관측을 확보했다고 주장하지 않는다.

기록 누락·실제 음료 함량 오차·수면 부족·스트레스·음주·추가 섭취는 모델 오차와 구분하기 어렵다. 종료 구간이 있는 관측에서는 마지막 섭취와 관측 종료 사이 새 섭취가 있으면 해당 체감 결과의 귀속을 보류한다. 야간 섭취는 실제 대상 구간을 기준으로 평가한다. 시간대 변경·오랜 회상·아직 끝나지 않은 체감 구간은 별도 분류한다. 일일 방향 응답은 대상 날짜 기록만 연결하며 다음 날 섭취를 배제하지만, 이것이 추가 섭취나 교란의 영향을 통계적으로 제거하는 방법은 아니다.

연구에서는 체크인을 제공할 기회, 응답/건너뜀/미응답, 예측 노출, 보류 사유를 구분해 누락의 선택 편향을 점검해야 한다. 현재 앱에서 팝업 닫기는 세션 내 상태이며 저장하지 않는다. 이전 버전의 건너뜀과 현재 닫기를 같은 관측 자료로 간주하지 않는다. 저장 자료에 없는 노출·기회 정보를 사후 생성하지 않는다. 연구에서 필요한 추가 계측은 범위를 정하고 동의 후 별도 구현한다. 미응답이 무작위라고 가정한 결과만 보고하지 않고, 주요 누락 패턴별 민감도 분석을 함께 제시한다.

## 불확실성 보고

사용자 간 일반화를 말할 때는 사용자 단위 재표집으로 개인화와 기본 모델의 **짝지어진 오차 차이** 구간을 계산한다. 같은 사용자의 여러 날을 독립 표본처럼 세어 구간을 좁히지 않는다. 사용자 내 시간적 의존성이 크면 사용자 내 연속 블록을 고려한 방법을 사전에 정한다. 한 사용자의 소수 응답으로 신뢰구간이나 정확도 보장을 표시하지 않는다.

95% 구간을 보고한다면 대상 추정량(예: 사용자 평균 구간 거리의 모델 간 차이), 분석 단위, 방법, 표본 수, 가정과 누락 처리를 적는다. 이는 미래 특정 개인의 95% 예측 구간이나 mg 정확도와 다르다. 자료가 적으면 점수·유효 건수·범위를 기술하고 검증 부족으로 남긴다.

## 운영 gate와 민감도 분석

기존 비교 경로의 보수적 활성화·보류 규칙은 연구로 확인된 정확도 보장이 아니다. 일일 방향 보정은 이 성능 gate 없이 적용하는 수동 실험 기능이므로 별도로 표시한다. 현재 유효한 일일 응답이 있으면 과거 비교 경로의 성능 악화·모순 보류가 새 보정을 막지 않으며, 과거 평가 수치는 이력으로 보존한다. 시간대 변경과 장기 공백 보류는 유지한다. 향후 실제 성능 평가에서 후보가 기준 모델보다 개선되지 않거나 악화되면 기본 예측을 사용하는 운영 방식을 사전에 정한다. 반복 평가 중 우연한 개선만 골라 보고하지 않도록 기간과 주요 지표를 미리 고정하고 악화 사례도 남긴다.

구현 검증에서는 prior, 학습률, 규제 강도, 최대 보정 폭, 1회 변경량, 최소 평가 수, 개선 기준을 바꿔 반복/교대/결측/교란 시나리오를 실행한다. 실행한 설정과 결과를 별도 파일로 저장한다. 이 민감도 분석은 범위 제한·방향성·gate 안정성을 확인하는 합성 실험이며 사람 대상 성능 결과로 사용하지 않는다.

출시 보고에서는 **구현 완료**, **자동·화면 동작 검증**, **실제 사용자 예측 성능 미검증**을 분리한다. 실제 사용자 검증이 이뤄지기 전까지 UI는 '실험적 체감 예측'으로 표시한다.
