## 검증한 사용자 흐름

- 빈 홈 → 카페인 추가 Sheet → 아메리카노 150mg → 155mg → 기록 → 잔존량과 인체 상태 변경.
- 기본 글자 크기의 375px·390px 화면에서 밤 예상량 카드가 고정 추가 버튼에 가려지지 않는지 좌표 검사.
- 같은 Sheet에서 커피 카테고리 + → 아이콘 선택 → 이름·85mg 입력 → 저장 → 새 chip 자동 선택 → 기록.
- 새로고침 후 두 기록·커스텀 음료 유지, 합산 240mg과 HIGH_VISUAL 상태.
- 날짜별 기록, 카페인량 수정, 확인 후 삭제, 홈 계산 갱신.
- 직접 `/settings` 진입, 반감기 저장·새로고침 유지, 초기화 취소·실행.
- 브라우저 뒤로가기에서 Sheet 우선 닫기, 키보드 포커스 제한·복원, Esc.
- 200% 텍스트 확대에서 가로 overflow 없이 음료 선택·기록 가능.
- 저장 실패 시 오류 표시, 실제 저장되지 않은 기록을 홈에 표시하지 않음.
- 저장 도중 뒤로가기로 Sheet를 닫아도 저장 완료 후 추가 뒤로가기 없음.
- 삭제 후 앞으로가기로 삭제된 기록의 빈 창이 복원되지 않음.
- 인체 내부 액체의 앞·뒤 SVG 파형이 서로 다른 주기로 움직이며, `prefers-reduced-motion`에서는 정지.

단위 테스트는 반감기와 여러 기록의 합산, 미래 기록 제외, 자정·22시 경계, invalid 값, 저장 데이터 검증, 실패 전파, Toss와 브라우저 저장소 분리, iOS overlay 중첩 정리를 포함합니다.

## 공식 Devtools 모의 검증

별도 Chrome 390px에서 `npm run dev:toss`를 실행하여 다음을 확인했습니다.

- 라이트 테마 자동 적용.
- SafeArea mock 변경에 따라 42px CSS inset 실시간 반영.
- mock back 이벤트로 Sheet 닫기, 내부 경로에서 홈으로 복귀.
- iOS Sheet 열림/닫힘에 따라 swipe 비활성화·복원.
- 공식 mock Storage에 155mg 저장 후 reload 유지. 일반 브라우저 storage key에 별도 저장하지 않음.
- pageerror 0개.

실제 토스 iOS/Android 앱의 QR·네이티브 저장소·swipe·딥링크는 이 작업에서 실행하지 않았습니다. 콘솔 appName 등록과 실제 기기 테스트가 필요합니다. 번들은 생성했지만 업로드·배포하지 않았습니다.

## 적용한 판단

사용자가 요청한 OLED 디자인은 일반 웹 미리보기에 유지했습니다. 최신 Toss 비게임 체크리스트의 라이트 모드·floating 탭 조건은 Toss 런타임 테마로 분리 적용했습니다. 공식 출처는 `toss-integration.md`에 정리했습니다. 커스텀 음료 이름은 UI와 저장 로직 모두 30자로 통일했습니다.
